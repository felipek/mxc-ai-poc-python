# MXC AI-generated POC — Python

> **AI-generated proof of concept.** Code and documentation were generated by
> OpenAI Codex in response to user prompts. This is an unofficial experiment
> for [Microsoft MXC](https://github.com/microsoft/mxc), not a Microsoft project,
> an official Python SDK, or a production sandbox service.

A separate Python application that executes **Python workloads inside MXC**
by invoking its native executor with versioned JSON requests.
The runner, workloads, bootstrap helper, examples, and tests use Python's
standard library. **No Node.js, npm, JavaScript bridge, or pip packages.**

MXC itself is a native Rust program. Python controls it through `subprocess`;
the containment boundary is macOS Seatbelt, not a Python emulation.
This POC implements **macOS only** and rejects other operating systems.

## Quick start

Prerequisites:

- macOS ARM64 or x86_64, with **Python 3.9+**.
- Git, Cargo/Rust, and Xcode Command Line Tools to build the native executor.
  The pinned MXC source requests Rust 1.93; this POC was built with Rust 1.99.1.
- Internet access for the first source/dependency download.

```sh
git clone https://github.com/felipek/mxc-ai-poc-python.git
cd mxc-ai-poc-python
python3 -m mxc_poc bootstrap
python3 -m mxc_poc doctor
python3 -m mxc_poc demo
```

Bootstrap fetches the exact revision in [`mxc-source.json`](mxc-source.json),
builds **only** the native `mxc_darwin` Cargo package with its locked dependencies,
and installs the executable in `.local/bin/mxc-exec-mac`. It records the source
revision, compiler, and executable SHA-256 in `.local/runtime.json`.
Normal runs verify that local metadata matches the executable and source pin.
This checksum detects local drift; it is not a Microsoft release signature.

The upstream checkout and build cache stay in `.cache/mxc`. No upstream code
is modified or committed to this repository. Git and Rust are needed for
bootstrap, not for subsequent sandbox runs. No Microsoft account or API key
is required. After bootstrap, the scenarios need no Internet access.

`doctor` executes a real sandbox smoke check. Missing runtimes, incompatible
hosts, and failed scenarios produce a nonzero exit code; nothing is silently
skipped or run without containment.

## Run the lab

```sh
python3 -m mxc_poc list
python3 -m mxc_poc demo
python3 -m mxc_poc run readonly transform
python3 -m mxc_poc run network
python3 -m examples.run_python
python3 -m unittest discover -s tests -v
```

| Scenario | What the host verifies |
| --- | --- |
| `hello` | A Python interpreter runs inside MXC and returns JSON. |
| `readonly` | Input can be read, overwriting it raises a permission error, and the host file stays unchanged. |
| `transform` | Two orders produce `{"orders": 2, "total_cents": 6499}` in the directory granted write access. |
| `denied` | A synthetic private file is readable under a read grant, then inaccessible when an explicit deny is added over that grant. |
| `network` | A connection to a local TCP service succeeds under an allow policy, then gets `EPERM` or `EACCES` under a deny policy. Refusal and timeout do not count as permission denials. |
| `stream` | Stdin reaches Python; two stdout messages arrive at least 300ms apart; stderr is captured independently. |
| `timeout` | A ten-second workload starts, MXC terminates it at a one-second deadline, and the native timeout diagnostic arrives before the host watchdog. |

The three additional integration tests verify nonzero exit/stderr propagation,
rejection of missing-file errors as proof of denial, and exclusion of a
synthetic host environment secret from the workload.

All fixtures contain synthetic data. Each run uses a unique temporary directory
and removes it afterward, including on scenario failures. Input paths include
spaces and apostrophes to exercise command-line quoting.

## Use it from your Python code

From the repository root, no package installation is needed:

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import sys

from mxc_poc import Executor, Request
from mxc_poc.runtime import python_runtime_paths

with TemporaryDirectory() as work:
    request = Request(
        argv=[
            str(Path(sys.executable).resolve()), "-I", "-S", "-B", "-u",
            "-c", "import json; print(json.dumps({'answer': 6 * 7}))",
        ],
        cwd=Path(work),
        readonly=python_runtime_paths() + [str(Path(work).resolve())],
        timeout_ms=3000,
    )
    result = Executor().run(request)
    print(result.json_output())  # {'answer': 42}
```

`Executor.run(request, stdin="...")` returns a `Result` with `exit_code`, raw
`stdout` and `stderr`, output arrival events, elapsed time, parsed native
diagnostics, and `watchdog_expired`. `json_output()` rejects failed executions
before parsing stdout. The synchronous method owns an asyncio loop, so invoke
it outside an already running loop (or use `asyncio.to_thread`).

`network_allowed` defaults to `False`. `readwrite` and `denied` accept explicit
path lists. The workload environment contains only `PATH` and `LANG`.
The lab launches Python with isolated mode, no site initialization, no bytecode
writes, unbuffered I/O, and UTF-8 text handling.

On macOS, Python framework libraries and C extensions may live outside MXC's
default readable paths. `python_runtime_paths()` discovers the current
interpreter's standard library and its non-system dynamic dependencies with
`otool`; they receive explicit read-only access. It handles absolute library
paths, `@loader_path`, and `@executable_path`. Unresolved external `@rpath`
dependencies fail with a diagnostic instead of granting a broad host directory.

To use an independently installed compatible executor, set `MXC_EXECUTABLE`
to its absolute path, or pass that path to `Executor(...)`. Reports label it
as an external runtime and record its hash; its source/version is unverified.

## Reports and diagnostics

Each completed suite writes `reports/latest.json` and a timestamped JSON report.
They include the actual MXC configuration, native runtime revision and hash,
Python/host versions, stdout/stderr, arrival timestamps, warnings, errors,
per-scenario assertions, and the overall outcome. Temporary fixture paths in
the report refer to files already removed during cleanup.

The native executor inherits workload stdio. Python consumes stdout and stderr
concurrently, records live chunks, feeds stdin, and waits for the native exit.
The native JSON request uses **contract 1.0.0**, explicitly selects `seatbelt`,
and includes MXC's own execution timeout. There is no `--audit`, profile override,
or fallback to an unsandboxed process.

The host watchdog expires eight seconds after the configured native deadline.
It kills the executor process group as recovery and marks that run as a host
failure. It cannot satisfy the timeout scenario. The pinned executor reports a
timeout as `backend_error` with a specific message; the test checks that
diagnostic together with workload start, termination, and elapsed time.
Those stderr diagnostics are suitable for these trusted fixed probes; arbitrary
workloads could print lookalike JSON, so they are not authenticated evidence.

## Verification and limits

Verified on **macOS ARM64** with **Python 3.9.6 and 3.15.2** and the pinned MXC
revision: all seven scenarios. The three additional adapter integration tests
and the standalone Python API example are also exercised locally.

Linux, Windows, macOS x86_64, persistent container lifecycles, sandbox escape
resistance, and remote-host/CIDR filtering are not verified. The network test
uses only a synthetic loopback service. Its allow control grants both ingress
and egress because Seatbelt cannot combine allowed host loopback with denied
default ingress.

This is a demonstration using trusted probes, not an audited system for
running arbitrary submitted code. Read grants cover the Python standard library;
system access remains subject to MXC's backend baseline. The discovered paths
cover the bundled workloads, not every possible third-party Python extension.
